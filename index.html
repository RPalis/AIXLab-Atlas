UX Atlas: a field guide

One process, twenty-six instruments.

Every skill in this suite exists to move a prototype through one sequence: Discover, Decide, Design, Deliver, the same shape a design‑thinking studio would run by hand. This page is the map: what each stage is for, which skill you reach for inside it, and where the tools that don't belong to any one stage, or don't belong to the lifecycle at all, live.

Before Discover

Nothing exists yet

No README, no docs folder, not even a name for the thing. Two skills run before any of the four stages: one sets the table, the other gets the idea out of someone's head.

/setup

Bootstraps the repo's doc shell: README.md, a project AGENTS.md recording which skill owns which doc, and an empty docs/UNKNOWNS.md. Never touches application code.
/brief

Interrogates whoever already has the idea: product, audience, user types, core tasks, devices, competitors, constraints. Writes docs/PRODUCT_BRIEF.md, the domain brief persona expects as input.
01

Stage One

Discover

Understand the users and the problem before proposing anything. Everything downstream inherits what gets settled here.

/workshop

Plans a design-thinking working session: activities selected by phase and timing, a written agenda, optional FigJam board or slide deck.
/digitize

Turns photos of a physical whiteboard or sticky-note board into a deck, doc, CSV, or a replicated FigJam board.
/interview

Phase-aware research kit: question bank, script, synthesis template. Loops back here later in validation mode.

discoveryvalidation
/persona

Formalizes user archetypes, mental models, and a chronological "Day in the Life" walkthrough that later skills read from directly.
02

Stage Two

Decide

Frame the problem, scope the objects, make the calls that get expensive to reverse once code exists.

/concepting

Interactive OOUX/ORCA walkthrough (Objects, Relationships, Calls-to-Action, Attributes), seeding the object map before any code exists.

planaudit
/interrogate

Interrogates a hard call one question at a time until there's shared understanding, not a guess dressed up as a decision.

↻ also usable anytime
/decisions

Writes a decision up as a short, permanent ADR, including the alternative that seemed obvious and why it got rejected.

↻ also usable anytime
03

Stage Three

Design

Build the actual prototype. The largest stage: scaffolding, tokens, a find/fix craft loop, and the documentation that keeps the system legible as it grows.

/scaffold

React 19 + TypeScript + Vite + Tailwind base scaffold, plus an optional site-type layer: dashboard, chatbot, marketing site, CRM.
/tokens

Establishes the two-layer token architecture (raw palette, then auto-flipping semantic roles) and generates DESIGN.md.
/forge

Casts a dedicated brand token preset for a new company or sub-brand from live CSS, a brand guide, or a verified hex matrix.
/audit

Finds problems, never fixes them. Craft mode feeds refine directly below; a11y runs once the UI has stabilized.

craftcodea11y
/refine

Fixes and unifies what audit's craft mode found: micro-interactions, responsive grids, dark-mode tuning, visual polish.
/storybook

Organizes the UI into the five Atomic Design tiers, builds Storybook stories, embeds the viewer in the prototype's own menu.
/map

Two modes: site generates the route/component graph three ways (interactive modal, Mermaid, SVG); flow turns a journey or workflow into a Mermaid flowchart. Either can export to FigJam.

siteflow
04

Stage Four

Deliver

Ship it, validate it, hand it off, and loop back to Discover for whatever the next round of real usage surfaces.

/audit

Code mode: token adherence, structure and reuse, mechanical hygiene, run before anything goes out the door.

code
/package

Builds the static handoff bundle: the full three-folder package for a developer, or the bare-essentials production folder.

fulllite
/showcase

Builds a shareable presentation from the prototype: a static PDF/PowerPoint deck, or a live reveal.js web deck.
/guide

Writes end-user documentation: a Getting Started section, then a phase-by-phase walkthrough of the real product.
/requirements

Reads the built prototype back into product language: Epics containing Features with user stories and acceptance criteria. Optional Jira/ADO export once an MCP server is connected.

How to actually use this

  1. 01Stages read top to bottom, but real projects don't. A mid-Design prototype can send you back to Discover after a workshop, mid-thought.
  2. 02Not sure where you are right now? Run /help. It reads the repo's actual files and tells you the next move, not the whole map.
  3. 03A multi-mode card means one skill, several jobs. Say the mode (/audit craft), or the skill will ask which you mean.

Usable Anytime

The tool belt

Not gated to a stage. Reach for these from anywhere in Discover through Deliver, whenever the situation actually calls for them.

/help

Reads the current repo's real state and recommends the next 1-3 skills, with the reason: the situational counterpart to this page.
/router

The full browsable index this page is drawn from: every skill, every phase, in one interactive reference.
/note

The lowest-ceremony capture in the suite: a quick thought dropped into docs/notes/my-notes/ and folded into the wiki immediately. No separate compile step to remember.
/wiki

Compiles docs/notes/ and any other document dropped into docs/ into a small, interlinked markdown wiki as the project accumulates them, including a constellation graph view.
/figma

Moves work to and from Figma, whichever direction the moment calls for.

captureimportsync

Meta: Managing the Suite Itself

The one tool outside the map

Everything above moves a prototype forward. This one skill sits outside that lifecycle entirely: it manages the skill library itself, not a prototype.

/skill-manager

Install, delete, disable, enable, list, and sync skills in the shared library at ~/.agents/skills, symlinked into Claude Code and Gemini CLI. Also shows what any installed skill does.
