# Evidence rules

The discipline that makes this analysis trustworthy. It outranks completeness, symmetry, and
deadline. Read before Phase 4; keep open through Phase 7.

## The six rules
1. **Transcripts only.** Never invent or embellish. Never assume a question was asked. If a claim
   cannot be verified from the transcripts, write `NOT VERIFIED — [why]`.
2. **Verbatim quotes with interview numbers.** Every quote is word-for-word and tagged with its
   interview number, e.g. `"…" — #3`.
3. **Weak signal.** A theme supported by fewer than two quotes is labelled `WEAK SIGNAL` so it is
   not over-read.
4. **Absence of evidence is never a finding.** "No one mentioned X" is not "X is not a problem".
   Record it as an open question for further research, never as a conclusion.
5. **References are structure only.** A supplied sample output shows layout and content order. It
   is never analysed as user input.
6. **No redundancy.** Say each thing once, in the place it belongs.

## Confidence tag — on every finding
| Tag | Meaning |
|---|---|
| `Verified` | Directly supported by ≥2 verbatim quotes from different interviews. |
| `Weak Signal` | Supported by only one quote, or a single interview. Real, but do not build on it alone. |
| `Not Verified` | Cannot be established from the transcripts. State why. Remove before final sharing. |

## The ⚠️ self-check
Before delivering, re-read every quote against its source. Any quote you are not 100% certain is
verbatim gets a ⚠️. A ⚠️ quote is not usable as `Verified` evidence until confirmed.

## Says vs does
Behaviour beats stated preference. When a user *says* one thing but their described workflow or
workaround shows another, record the contradiction — the workaround is the real unmet need.
