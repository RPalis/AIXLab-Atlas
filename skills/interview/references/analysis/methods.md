# Methods

How to run the "Generate insights" and "Find patterns" phases with rigour. Use these as the
mechanism; the card's structure and vocabulary stay primary.

## Thematic analysis (6 steps)
1. **Familiarise.** Read all transcripts before coding anything. Get the landscape first.
2. **Initial coding.** Tag each observation, quote, or data point with a short descriptive code.
   Be generous — easier to merge than to split.
3. **Theme development.** Group related codes into candidate themes. A theme captures something
   important in relation to the research goal.
4. **Theme review.** Check each theme against the data. Enough evidence? Distinct from the others?
   Coherent story? A theme under two quotes is a `WEAK SIGNAL`.
5. **Refine and name.** Give each theme a short name and a one-line definition.
6. **Report.** Write themes as findings with verbatim evidence and interview numbers.

## Affinity mapping
One observation per note. Cluster by similarity — do not pre-define categories, let them emerge.
Label each cluster. Count `n of N` interviews per cluster. Outliers are interesting; do not force
them into a cluster. Record the affinity map as `(n) out of (N) interviews chose (x) and (y)`.

## Says vs does (the core lens)
The card's promise is *what users need, not just what they say.*
- Weight **behaviours and workarounds** above **stated preferences**.
- A workaround is an unmet need in disguise — log it.
- Note **intensity signals**: emotional language, frequency of the problem, and how much effort
  the user spends working around it.
- When stated preference and described behaviour conflict, that contradiction is a finding.

## Surprises and contradictions
Keep these separate from themes. Where interviews disagree, that usually reveals distinct user
segments rather than noise. Where a finding challenges the team's prior assumption, name it.

## Sentiment
Tag each pain point / need / workaround with sentiment (frustrated, resigned, delighted, anxious…)
drawn from the transcript language, not assumed.

## Triangulation (optional, if extra sources exist)
If quantitative survey results, product analytics, or a feedback connector are available, use them
to **prioritise** qualitative themes (a theme that also shows up in the numbers is stronger) and
to **explain** anomalies. Present combined evidence honestly; when sources disagree, report the
disagreement rather than choosing one.
