# First run and empty states

The first minute decides whether a user continues. Design it as its own flow.

## Contents

- Principles
- Patterns
- Empty state anatomy
- Checklist

## Principles

- Get to the first useful result fast. Ask only for what the next step needs.
- Teach by doing. A short task beats a long tour.
- Let the user skip. Never block the product behind a tour.
- Show progress when setup has more than two steps.

## Patterns

| Pattern | Use when | Note |
|---|---|---|
| Sample data | The value only shows with data | Label it as sample and give a one-click clear |
| Checklist (3 to 5 items) | Setup has several independent steps | Persist progress; allow dismiss |
| Inline hint | One control needs explaining | Dismiss forever after first use |
| Short tour (max 4 steps) | A non-obvious layout | Skippable; reopen from help |
| Template picker | Blank pages stall users | Include a "start empty" choice |

## Empty state anatomy

1. A plain illustration or icon (optional, small).
2. A headline that says what belongs here.
3. One sentence on the benefit.
4. One primary action. A secondary link to learn more is allowed.

## Checklist

- A new user reaches a first success in under a minute.
- Every empty screen has a headline, a benefit and an action.
- Nothing in the first run needs a tour to understand.
- A returning user never sees first-run UI again.
